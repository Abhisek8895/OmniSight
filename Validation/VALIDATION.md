# Code Validation & Fix Output

This module validates CSS and React fixes generated by the VLM pipeline.

## Workflow

Task 4 generates and extracts the code.

The validation module receives the generated fix and performs basic validation before passing it to the repair workflow.

The workflow is:

```text
Task 4: Code Generation & Extraction
                ↓
        Generated Fix
                ↓
        Code Validation
                ↓
     ┌──────────┴──────────┐
     ↓                     ↓
 Valid                  Invalid
     ↓                     ↓
Validated Output       Rejected Output
```

## Validation Checks

The validator currently performs the following checks:

1. **Code existence** — Rejects empty or whitespace-only code.
2. **Supported code type** — Supports `css` and `react`.
3. **Minimum code length** — Rejects code shorter than 10 characters.
4. **Maximum code length** — Rejects code longer than 5000 characters.
5. **Structured output** — Returns a clear validation status and reason.

## Input

The validation module expects a JSON object in the following format:

```json
{
    "code_type": "css",
    "code": ".checkout-button { margin-bottom: 20px; }"
}
```

Supported code types:

```text
css
react
```

## Output

### Valid Code

```json
{
    "status": "validated",
    "code": ".checkout-button { margin-bottom: 20px; }",
    "code_type": "css",
    "reason": "Basic validation passed"
}
```

### Invalid Code

For example, if an unsupported code type is provided:

```json
{
    "status": "rejected",
    "code": null,
    "code_type": "python",
    "reason": "Unsupported code type: python"
}
```

## Project Files

```text
Validation/
├── code_validator.py
├── fix_output.py
├── sample_fix.json
├── test_validator.py
└── README.md
```

### `code_validator.py`

Contains the core validation logic.

It checks:

- Whether code is provided
- Whether the code type is supported
- Whether the code meets the minimum length
- Whether the code stays within the maximum length

### `fix_output.py`

Connects the generated fix to the validation logic and produces the final structured output.

### `sample_fix.json`

Contains sample Task 4-style input used for testing the validation workflow.

### `test_validator.py`

Contains automated tests for the validation logic, including:

- Valid CSS
- Valid React
- Empty code
- Unsupported code type
- Code that is too short

## Running the Validation

Run the sample validation:

```bash
python fix_output.py
```

Run the automated tests:

```bash
python -m pytest test_validator.py
```

Expected result:

```text
5 passed
```

## Current Scope

This module performs **basic validation only**.

It does not currently perform:

- Full CSS syntax validation
- Full React/JSX syntax validation
- Browser-based testing
- Applying the generated fix to the website
- Verifying whether the UI defect was actually fixed

These checks can be added later as the VLM repair pipeline is integrated.

## Integration with Task 4

Once Task 4 generates and extracts the repair code, its output can be passed directly to:

```python
prepare_fix(fix_data)
```

The validation module will then return either a validated or rejected repair result for the next stage of the OmniSight repair workflow.
