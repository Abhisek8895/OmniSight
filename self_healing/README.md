# Agentic Self-Healing Loop

## Overview

The Self-Healing Loop is responsible for automatically checking whether an AI-generated UI fix successfully resolves the detected defect.

It connects the repair and verification steps into a controlled retry loop.

## Workflow

The self-healing process follows this flow:

```text
AI-Generated CSS Fix
        ↓
Apply CSS Fix
        ↓
Take New Screenshot
        ↓
VLM Verification
        ↓
Is the Defect Fixed?
     ↙         ↘
   Yes          No
    ↓            ↓
  Finish     Retry Fix
                 ↓
          Maximum Retries?
             ↙       ↘
           Yes        No
            ↓          ↓
          Stop       Retry
```

## Responsibilities

The self-healing loop is responsible for:

- Receiving the validated CSS fix generated by the AI.
- Applying the proposed fix to the local webpage.
- Capturing a new screenshot after the fix.
- Sending the updated screenshot for VLM verification.
- Determining whether the UI defect has been resolved.
- Retrying the repair when the defect is not fixed.
- Limiting the number of repair attempts.
- Safely stopping when the maximum retry limit is reached.

## Retry Handling

The loop uses a maximum retry limit to prevent continuous repair attempts.

```python
MAX_RETRIES = 3
```

The process stops when:

1. The VLM confirms that the defect is fixed, or
2. The maximum number of repair attempts has been reached.
